# 前端审查与修复记录（2026-10-28）

## 结论

业务和数据可靠性基础较好，前端问题主要是设计规范脱节、可访问性不足、信息层级拥挤和状态反馈错误。采用局部修复而非重写，品牌图片与吉祥物暂未调整。

## 已修复

| 范围 | 原问题 | 当前结果 |
| --- | --- | --- |
| 人物时间 | 列表按经度估算，忽略半时区和 DST | 列表与图谱共用 IANA 时区；未知时区显示待确认 |
| 颜色对比度 | 浅色 primary 配白字仅约 2.24:1 | 五套主题的语义前景均要求高对比，自动测试要求至少 4.5:1 |
| API Key | 输入明文、成功显示错误色、首次保存失败静默 | 默认遮蔽、真实成功状态驱动颜色、失败明确提示 |
| 数据重置 | 重置后创建空白用户，无法回到首次引导 | 清除身份、偏好与附件，明确进入首次引导 |
| 自定义提醒 | 创建和编辑缺少时间基准，不能按人物当地时间 | 复用时区选择器并持久化 timezoneMode，未确认时区强制用户时间 |
| 历史与文案 | 长期日期使用 UTC 直显，统计和建议有误导性表述 | 按设备本地时区显示，使用已记录天数和中性称呼 |
| 设计令牌 | 大卡片与普通卡片同为 16px，lg 为 20px | cardInnerLarge 与 lg 统一为 24px |
| 暗色一致性 | 组件固定浅色变体、暗色头像带阴影 | 使用当前 ColorScheme/taColorsFor，暗色头像取消阴影 |
| 触控与语义 | 图标按钮 40px，隐藏长按清除历史 | 默认至少 48px，次要操作进入“更多操作”菜单 |
| 小念首屏 | 正常健康卡长期占位，次要操作分散 | 健康卡仅在异常或未知证据时显示，操作集中菜单 |
| 提醒配置 | 三个操作与摘要挤在一行，新建入口重复 | 内容与开关一层、编辑历史一层，摘要最多两行，单一新建入口 |
| 列表动画 | 延迟随索引无限增长 | stagger 最大 300ms，修改范围内支持减少动态效果 |
| 成就庆祝 | 每次进入为所有旧成就播放动画 | 首次静默建立基线，只庆祝后续新解锁 |
| 组件重绘 | 进度环忽略 backgroundColor 变化 | backgroundColor 纳入 shouldRepaint |

## 新增回归证据

- 五套浅色 primary/secondary/tertiary 对比度。
- 24px 令牌、48px 图标按钮、暗色头像和徽章。
- 加载与庆祝动画的减少动态效果处理。
- 健康卡正常隐藏、异常/未知显示。
- 小念菜单和提醒配置在 390px、200% 字体下的表现。
- stagger 上限、人物未知时区和成就首次静默。

完整结果为静态分析 0 项、225 项测试通过、三 ABI 构建成功。

## 暂缓与后续验收

- 品牌角色、图片水印、透明背景和资产体积暂不调整，避免没有视觉方向时盲目重做。
- 真机上的最终留白、中文/西文混排、动画流畅度和实际审美仍需视觉验收。
- 旧独立聊天页和大型小念文件可在后续按业务变化逐步拆分，不把行数本身当成重写理由。
